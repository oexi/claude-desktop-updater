# claude-desktop-updater

Checks every day for new Linux releases of [Claude Desktop](https://code.claude.com/docs/en/desktop-linux). When a new version is out, it packages it for several package managers and publishes it as a GitHub Release.

| Format | Architectures | Source |
|---|---|---|
| `.deb` (apt) | amd64 / arm64 | **Official package**, republished unchanged |
| `.pkg.tar.zst` (pacman) | x86_64 / aarch64 | Repackaged from the official .deb |
| `.rpm` (dnf / zypper) | x86_64 / aarch64 | Repackaged from the official .deb |

## How it works

```
check ──► build (pacman×2, rpm×2, in parallel containers) ──► release
```

1. **check**: `scripts/check-upstream.sh` reads Anthropic's official apt repository and verifies the whole chain of trust:
   the signing key pinned to fingerprint `31DDDE24…CACE` → the GPG signature and `Valid-Until` date of `InRelease`
   → the SHA256 of the `Packages` index → the SHA256 of each `.deb`.
   `scripts/release.sh status` then checks whether release `v<version>` is complete.
   A build only starts if the release does not exist yet or is missing any expected file.
2. **build**: pacman packages are built in an `archlinux:base-devel` container, RPMs in a `fedora:latest` container.
   The aarch64 packages are cross-packaged on x86_64 runners: the job only repackages prebuilt files, nothing is compiled.
3. **release**: downloads the official .deb files again (their hashes must match the signed index), writes `SHA256SUMS` and install instructions,
   then creates or updates the release. Files left behind by an older pkgrel are deleted automatically.

Triggers:

- **Scheduled**: once a day at 01:17 UTC (schedules only run on the default branch).
- **Manual**: Actions → *Claude Desktop Release* → *Run workflow*. Tick `force` to rebuild a release that is already complete.

## Packaging details

- **pacman**: based on the PKGBUILD of the AUR package [`claude-desktop`](https://aur.archlinux.org/packages/claude-desktop). It keeps the translated dependencies, the Wayland launcher, and the virtiofsd / OVMF path shims that Cowork needs.
- **RPM**: library dependencies are generated by rpm from the binaries themselves (as sonames), so the same package resolves on Fedora, RHEL and openSUSE.
  Of the non-library dependencies, `xdg-utils` and `xdg-desktop-portal` are required; everything else (QEMU, OVMF, keyring, …) is a Recommends.
  Fedora needs no path shims: the app already looks for `/usr/libexec/virtiofsd` and `/usr/share/OVMF/OVMF_CODE.fd`.
- Both formats ship the distribution-neutral parts of the .deb's postinst script as static files: the GNOME Shell search provider, the MIME types for `.mcpb/.dxt/.skill`, and the `ccd` launcher link (only when upstream ships `resources/bin/ccd`).
- `packaging/PKGREL` is the packaging revision, used as both the pacman pkgrel and the RPM Release. Bump it after changing anything under `packaging/`, and the next run rebuilds and replaces the old packages.

Verified locally in containers (version 4.23118.1): both formats build for both architectures, the ELF architecture is correct, chrome-sandbox keeps its setuid bit, and dependencies resolve fully on Arch, Fedora 45 and openSUSE Tumbleweed.

## Local use (Arch Linux)

`claude-desktop-update` uses the same scripts and templates as CI to check, package and install the latest version on the local machine. It must run from the repository directory; you can symlink it into `~/.local/bin`:

```bash
./claude-desktop-update --check      # check only: exit 0 = up to date, 10 = update available
./claude-desktop-update              # check → package → pacman -U
./claude-desktop-update --build-only # package without installing
```

If Claude Desktop is running, it warns you before installing (replacing files the app is using can crash it).

## Layout

```
.github/workflows/release.yml   scheduled / manual workflow
scripts/check-upstream.sh       read and verify the official apt repository
scripts/fetch-deb.sh            download a .deb and verify it against the signed index
scripts/build-pacman.sh         .deb → .pkg.tar.zst
scripts/build-rpm.sh            .deb → .rpm
scripts/release.sh              status / publish: decide whether to build, publish the release
scripts/common.sh               shared constants, asset naming, architecture mapping
packaging/arch/PKGBUILD.in      pacman packaging template
packaging/rpm/*.spec.in         RPM packaging template
packaging/common/claude-desktop.sh  Wayland launcher (shared by both formats)
packaging/PKGREL                packaging revision
claude-desktop-update           local updater for Arch
```

## Notes

- **License**: Claude Desktop is proprietary software from Anthropic (`License: Proprietary`). Publishing these packages in a release redistributes its binaries. **Keeping this repository private for personal use is recommended.**
- In public repositories, GitHub disables scheduled workflows after 60 days without commits (publishing releases does not count as activity). Private repositories are not affected.
- Private repositories use Actions minutes: about 1 minute per daily check, about 5–10 minutes for a full build when a new version is out. Build artifacts are kept for 1 day.
- The `.rpm` and `.pkg.tar.zst` packages are unsigned; verify them with the `SHA256SUMS` file in the release.
